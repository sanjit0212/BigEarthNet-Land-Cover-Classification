1. DID I USE THE FIRST 40K PATCHES?
-----------------------------------------------------------
No, you did NOT use the "first 40k" patches. 

If you had just taken the first 40k images from the 80GB folder, your dataset would have been extremely biased (for example, the first 40,000 images might all be from a single geographic region or a single season, meaning the model would fail completely on different environments).

Instead, your Python script (`0_create_subset_from_archive.py`) performed a "Stratified Random Sample". 
1. It looked at the total distribution of classes across the entire 80GB dataset.
2. It randomly picked exactly 40,000 images in a way that matches the exact class proportions of the massive dataset. 
3. This guarantees that your 40k subset is a miniature, statistically accurate representation of the original 80GB dataset.

2. CLARIFY THE ROLE OF THE PARQUET FILES
-----------------------------------------------------------
Parquet is an incredibly fast, highly-compressed, columnar storage file format. It is the gold standard for Big Data and Hadoop.

Why did we use Parquet?
The original dataset consists of individual `.tif` image files. Hadoop and Spark are TERRIBLE at reading millions of tiny, separate image files. If Spark had to open 40,000 separate image files across a distributed cluster, the network overhead would bring the cluster to a halt.

What did we do?
In `2_extract_features.py`, we mathematically processed the images (extracted the NDVI and NDWI metrics). Then, instead of saving them as individual files, we combined all 40,000 rows into a single `features_40k.parquet` file. 

This means:
- The data is compressed (saving space).
- The data is in a columnar format (Spark can read it instantly).
- Hadoop only has to distribute 1 single Parquet block across the DataNodes, rather than managing 40,000 individual files.
